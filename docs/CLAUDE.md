## 2. Strategic decisions (the brainstorming, already done)

**Brain is the primary track.** BraTS2020 has real tumor ground-truth masks
— it's the only place you can produce legitimate Dice/Jaccard/Hausdorff
numbers. That covers the full 30% segmentation weight with real evidence,
not a hand-wave.

**Spine is deliberately lighter — classical/unsupervised, not deep
supervised.** The offline spine dataset has zero ground truth and no
external data is allowed, so a "trained segmentation model" claim there
would be dishonest (nothing to train against). The problem statement itself
suggests self-supervised/unsupervised methods for exactly this situation —
lean into that framing, don't apologize for it.

**2D slice-based processing, not 3D volumetric.** MONAI's actual pretrained
BraTS segmentation bundle documents a 16GB+ GPU memory requirement — an
RTX 4050 (6GB typical) can't run that. Slicing volumes into 2D axial images
and training a 2D U-Net per-slice is a standard, well-documented workaround
for exactly this constraint. This is a legitimate, citable design choice
for the report, not corner-cutting.

**Multi-modal input for segmentation.** All 4 modalities (T1/T1c/T2/FLAIR)
are stacked as input channels for the segmentation model — different
modalities highlight different tumor sub-regions (T1c → enhancing tumor,
FLAIR/T2 → edema), and this measurably improves real Dice scores vs a
single modality.

**Synthetic MRI-realistic degradation for enhancement training pairs.**
BraTS has no "noisy version" of each scan — so pairs are built by
synthetically degrading BraTS's own clean scans. Uses MRI-*correct*
degradation, not generic image noise: Rician noise (the correct noise
model for MRI magnitude images — plain Gaussian would be a real
methodological error worth avoiding) + a smooth multiplicative bias field
(simulates RF coil inhomogeneity, ties directly to the problem statement's
"artifact correction" requirement) + mild blur.

**Full metric suite via existing libraries, not reinvented from scratch**
(verified working, see §3):
- `pyiqa`: PSNR, SSIM, FSIM, GMSD, VIF, BRISQUE, NIQE, PIQE, LPIPS
- `medpy.metric.binary`: Dice, Jaccard, Hausdorff Distance, Average Surface
  Distance, precision, recall, sensitivity, specificity
- Hand-rolled (trivial, in `metrics.py`): MSE, RMSE, UQI, Entropy

**Case-level train/val split, never slice-level** — slices from the same
patient are highly correlated; splitting by slice leaks information and
inflates reported metrics. `brain_dataset.py`'s `split_cases()` already
does this correctly.

with `INTER_CUBIC` can overshoot the input value range near sharp edges
(ringing) — slices were coming out slightly outside [0,1]. Fixed by
clipping immediately after every cubic resize in `nifti_utils.py`. If you
add any new resize calls elsewhere, clip after them too.

## 4. What's left to build

### 4a. `train_segmentation_brain.py` (highest priority — 30% of grade)
Mirror `train_enhancement_brain.py`'s structure, but:
- Dataset: `BrainSegmentationDataset` (already built, 4-channel input, mask target)
- Model: `SegmentationUNet(num_classes=4, in_channels=4)`

- Per epoch: report training loss, validation loss, **and** per-class Dice/Jaccard
  (via `metrics.multiclass_segmentation_metrics`) for the 3 non-background
  classes (necrotic, edema, enhancing)
- Also compute Hausdorff Distance + Average Surface Distance per class on
  validation set (already in `metrics.py`'s `segmentation_metrics`)
- Report training loss curve, validation loss curve, convergence epoch,
  overfitting gap — the problem statement explicitly asks for these

### 4b. `dataset_stats.py` (Stage 1, 20% of grade)
Must run on **both** BraTS (standard training dataset) and the hackathon's
own offline Brain + Spine datasets. For each, compute and report:
contrast, sharpness (Laplacian variance is the standard cheap proxy),
edge strength (Sobel gradient magnitude mean), noise level (e.g. estimate
via high-frequency wavelet/Laplacian residual, or std in a flat background
region), mean, standard deviation. Also: comparison between Brain/Spine
submodalities, division of dataset by submodality (T1/T2/FLAIR/STIR),
and an explicit train/test/val enumeration. This is 20% of the grade and
currently has zero code — don't leave it for last.

### 4c. `spine_pipeline.py` (classical/unsupervised, per §2's Spine decision)
- Enhancement: CLAHE (`cv2.createCLAHE`) — classical, fast, defensible,
  directly named in the problem statement's own Stage 2 suggestions
- Segmentation: unsupervised — k-means clustering on intensity (or
  Otsu multi-thresholding) to separate candidate disc/vertebra/CSF regions.
  Frame this explicitly as "exploratory unsupervised ROI segmentation" in
  the report — honest, and matches what the problem statement itself
  suggests for a no-ground-truth situation
- No training needed for this one — it's classical CV, should be quick

### 4d. `coco_export.py`
Convert final predicted masks (Brain: from the trained segmentation model;
Spine: from the classical pipeline) into COCO JSON using `pycocotools.mask`
(already confirmed installable). One JSON per dataset (Brain/Spine), or
combined — check if the organizers specified a format, otherwise combined
is fine.

### 4e. `inference_report.py`
Runs the trained Brain enhancement + segmentation models, and the classical
Spine pipeline, on the **actual hackathon offline dataset** (not BraTS, not
synthetic). Since there's no ground truth for that data:
- Enhancement: report **no-reference** metrics only (BRISQUE/NIQE/PIQE/Entropy
  — these don't need a clean reference, see `metrics.no_reference_metrics`)
- Segmentation: no Dice/Jaccard possible without ground truth — report
  qualitative visualizations (overlay masks) + note this limitation
  explicitly and honestly in the report rather than fabricating numbers
- Also produce the before/after visual panels for the presentation slides

### 4f. Benchmarking script (small but explicitly required deliverable)
"Systematic comparison study... based on Inference Latency, Throughput,
GPU/CPU utilization, Memory Consumption, Model complexity" is called out
twice in the problem statement (once for enhancement, once for
segmentation). A short script that times `model(input)` over N runs,
reports ms/image and images/sec, `torch.cuda.max_memory_allocated()`, and
`sum(p.numel() for p in model.parameters())` covers this cheaply — don't
skip it, it's easy points that most teams will forget.

## 6. Known gotchas

- LPIPS, BRISQUE, NIQE, PIQE (`pyiqa`) download small pretrained weight
  files on first use — needs real internet once, then cached. Should be a
  non-issue with venue wifi, but don't be surprised by a delay on first run.
- Watch GPU memory on the RTX 4050 (6GB): start with `base_filters=32`,
  `batch_size=8`. If you get an OOM error, drop batch_size first, then
  base_filters. Consider `torch.cuda.amp.autocast()` mixed precision if
  you need more headroom — free speed + memory win, worth adding if time
  allows.
- Always split by case, never by slice (see §2) — every dataset class
  in `brain_dataset.py` already respects this, don't accidentally break
  it if you modify the split logic.
- `medpy`'s `hd`/`asd` (Hausdorff/surface distance) throw if either mask
  is completely empty — `metrics.segmentation_metrics` already guards
  this and returns `None` instead of crashing. Keep that guard if you
  touch this function.
